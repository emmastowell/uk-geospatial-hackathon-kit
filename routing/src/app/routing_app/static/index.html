      How it works

      This App runs Valhalla, an open-source routing engine, over the OpenStreetMap road network. It answers four kinds of question: how to get from one place to another, where you can reach within a time, how long it takes between many places, and which roads a GPS trace followed. The map shows the engine at work; notebooks and other code use the same engine through an HTTP API.

      Architecture

      There are two parts: a job that turns OpenStreetMap data into routing tiles, and an App that loads those tiles and answers requests. A Unity Catalog volume sits between them, so the tiles can be rebuilt without redeploying the App.

      Building the tiles

      1. The build-valhalla-tiles job streams the OpenStreetMap extract named by its osm_url parameter into the volume (about 2.2 GB for Great Britain).
      2. On a classic single-node cluster, the tools in the pyvalhalla wheel build an admin database (country and region boundaries, which set rules such as driving on the left), then the routing tiles, then pack the tiles into one indexed tar file.
      3. The job copies the tar file to the volume, followed by a manifest.json that describes it. A full Great Britain run takes about 20 minutes, including cluster start-up; a small extract such as the Isle of Wight builds far faster.

      Serving requests

      1. When the App starts, its service principal reads the manifest from the volume through the Files API. The App has READ VOLUME on the volume and nothing else.
      2. It copies the tile file to its local disk, because Valhalla reads tiles by memory-mapping a local file. This takes about a minute; the status at the top of the page shows progress.
      3. It loads one Valhalla worker per CPU over that file and checks that the graph holds tiles before it reports ready.
      4. Each request passes through the Databricks Apps proxy, which signs the caller in. FastAPI hands the request to a free worker and returns Valhalla's JSON response unchanged.

      Design choices

      • Classic compute for the build. Valhalla is a native C++ engine that needs plenty of memory and fast local disk for its intermediate files, so the build runs on one classic node rather than serverless compute.
      • Tiles in a volume. The volume holds the only lasting copy. The App keeps a disposable copy, and a rebuild is a job run followed by an App restart.
      • A pool of workers. A Valhalla worker handles one request at a time, so the App keeps one per CPU and lends each request a free one. Valhalla releases Python's global interpreter lock while it works, so the workers run in parallel.
      • Python 3.12 with uv. The pyvalhalla wheel needs Python 3.12 or later. Apps that declare dependencies with uv can choose their Python version; the default for Apps is 3.11.

      Concepts

      The routing graph and tiles

      Valhalla turns OpenStreetMap roads and paths into a graph: junctions become nodes and road segments become one-way edges, each carrying speeds, access rules and turn restrictions. The graph is cut into square tiles at three levels: motorways and trunk roads, other main roads, and local roads. Long journeys move up to the higher levels early, which is why a route from Land's End to John o' Groats takes a fraction of a second.

      Locations and snapping

      Requests start from latitude and longitude points. Valhalla matches each point to the nearest road the travel mode can use, searching up to 35 km away by default (set search_cutoff, in metres, to change this). Use locate to see where a point lands on the network. Error 171 means no suitable road was found.

      Travel modes

      The costing field picks the travel mode. Each mode has its own speeds, access rules and preferences, which you can adjust under costing_options, for example {"pedestrian": {"walking_speed": 4}}.

      CostingTravel modeUseful options
      autoCaruse_highways, use_tolls, use_ferry (0 to 1)
      pedestrianWalkingwalking_speed (km/h), use_ferry
      bicycleCyclingbicycle_type, cycling_speed, use_roads, use_hills
      busBus on roads open to buses (no timetables)As for auto
      truckLorryheight, width, length (metres), weight (tonnes)
      motorcycle, motor_scooter, taxiOther road vehiclesSee the Valhalla costing reference

      Routes and directions

      route returns a trip with one leg between each pair of locations. Each leg has a summary (length and time in seconds), manoeuvres with written directions, and a shape. Set directions_options.language to en-GB for British English directions and units to kilometers or miles. The shape is an encoded polyline with six decimal places: in Python, polyline.decode(shape, 6) from the polyline package turns it into points.

      Isochrones

      An isochrone is the area you can reach from a point within a time or distance. Ask for up to four contours, each a time in minutes or a distance in kilometres. Set polygons to true for areas rather than outlines; denoise (0 to 1) removes small islands and generalize (metres) simplifies the edges. The response is GeoJSON, which st_geomfromgeojson reads directly.

      Travel-time matrices

      sources_to_targets returns the time in seconds and the distance from every source to every target in one request, which is much quicker than separate routes. Cell [i][j] describes source i to target j. A null time means the matrix search did not resolve that pair; route it on its own.

      Map matching

      trace_route takes a GPS trace as shape and returns the route it most likely followed. trace_attributes returns the matched roads with their names, speeds and road classes. Set shape_match to map_snap for noisy GPS points.

      Optimised routes

      optimized_route puts the stops between the first and last location into the order with the shortest total time, then returns the route. Each location in the response carries its original_index.

      What the times mean

      Times assume free-flowing traffic. Valhalla takes speeds from OpenStreetMap tags and road types and adds costs for turns and junctions. There is no live or typical traffic and no public transport timetable data, so treat car times as off-peak and use them to compare places rather than to predict a particular journey.

      Joining results to the hackathon data

      Most hackathon tables carry an H3 resolution 8 cell (h3_8), and some carry GEOMETRY columns. To find what lies inside an isochrone, list the H3 cells it touches with h3_coverash3 to narrow the search, then keep exact matches with st_contains. Both need serverless compute.

      SELECT count(*) AS bus_stops
FROM hackathon.two_postcodes.naptan_stops
WHERE stoptype = 'BCT'
  AND h3_8 IN (SELECT explode(h3_coverash3(:isochrone_geojson, 8)))
  AND st_contains(st_geomfromgeojson(:isochrone_geojson), st_point(lon, lat, 4326))

      API

      Every Valhalla action is served under one base URL with Valhalla's usual request bodies, so the Valhalla API reference applies as written.

      Base URL: /api

      Send a JSON body with POST /api/<action>, or put the same JSON in a json query parameter with GET. Responses are Valhalla's JSON, unchanged. GET /api/health reports whether the tiles are loaded, which data they hold and the limits in force.

      Signing in

      Databricks Apps accept signed-in users and OAuth tokens issued for the App. They do not accept personal access tokens. Callers also need CAN USE on the App, which every workspace user has here.

      • In this browser you are already signed in, so the map and the console below call the API directly.
      • In a notebook, swap the notebook's own token for one issued for this App and send it as a bearer token. The notebook /Shared/routing/valhalla_quickstart wraps this in a small client with worked examples. The token lasts about an hour.
      • From a laptop, sign in with databricks auth login and send the token that databricks auth token prints. A service uses a service principal's OAuth credentials, and the service principal needs CAN USE on the App.
      import requests

context = dbutils.notebook.entry_point.getDbutils().notebook().getContext()
host, notebook_token = context.apiUrl().get(), context.apiToken().get()
app = requests.get(f"{host}/api/2.0/apps/valhalla-routing",
                   headers={"Authorization": f"Bearer {notebook_token}"}).json()
token = requests.post(f"{host}/oidc/v1/token", data={
    "grant_type": "urn:ietf:params:oauth:grant-type:token-exchange",
    "subject_token": notebook_token,
    "subject_token_type": "urn:databricks:params:oauth:token-type:personal-access-token",
    "requested_token_type": "urn:ietf:params:oauth:token-type:access_token",
    "scope": "all-apis",
    "audience": app["oauth2_app_client_id"],
}).json()["access_token"]

trip = requests.post(f"{app['url']}/api/route",
                     headers={"Authorization": f"Bearer {token}"},
                     json={"locations": [{"lat": 51.5308, "lon": -0.1238},
                                         {"lat": 51.5194, "lon": -0.1270}],
                           "costing": "pedestrian"}).json()["trip"]
print(trip["summary"]["length"], "km")
      TOKEN=$(databricks auth token --profile <profile> | jq -r .access_token)
curl -X POST "/api/route" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"locations":[{"lat":51.5308,"lon":-0.1238},{"lat":51.5194,"lon":-0.1270}],"costing":"pedestrian"}'

      Errors

      Errors use Valhalla's JSON shape, for example {"error_code": 171, "error": "No suitable edges near location", "status_code": 400, "status": "Bad Request"}.

      CodeMeaningWhat to do
      100The body is not a JSON objectCheck the JSON is valid
      106Unknown actionUse an action from the table above
      120Too few locationsSend at least two locations for a route
      125Unknown travel modeUse a costing from the travel modes table
      151, 152An isochrone over the time or contour limitAsk for up to four contours within the limits above
      154Locations further apart than the mode allowsCheck the limits above or split the journey
      170Locations in parts of the network that do not connectCheck both points are reachable by that travel mode
      171No suitable road near a locationMove the point, or check latitude and longitude are not swapped
      442No route between the locationsTry another travel mode or check access restrictions
      503The App is still loading its tilesWait until the status at the top of the page shows Ready
